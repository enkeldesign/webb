TURN DESIGN SYSTEM

A design-system review and living specimen built from the production game. It preserves TURN’s loud, tactile, friendly character while replacing accidental variation with named colour roles, a small geometry scale and repeatable components.

Reference page only. Production UI is unchanged.

01 · Current-state review

TURN already has a system. It is simply distributed.

The review covers the production styles that define Install, Home, track selection, The Lot, race controls, HUD, dialogs and feedback states. The strongest identity markers are consistent. Most drift sits in intermediate radii, shade naming and shadow increments.

Keep

Chunky ink construction

Near-black outlines, cream surfaces, offset hard shadows, heavy typography and saturated fields are the visual grammar of TURN. They make the interface feel physical and toy-like without looking childish.

Consolidate

Colour families and geometry

The same intent is often represented by neighbouring hex values, radii and shadow distances. These should become controlled scales with names, not a single flattened palette.

Retire

Unexplained one-off values

Values such as 13px, 15px, 17px and 21px radii create no distinct visual category. Raw colour values used only once also make future semantic changes unnecessarily expensive.

03 · Shape and elevation

Six shapes, four borders, three elevations.

The system should feel handmade, not arbitrary. Slight rotations and scene-specific silhouettes can stay expressive. UI containers should come from a small, teachable geometry set.

Use 50% for close, next/previous, radio markers, steering knobs and point indicators. Use pills for textual labels and elongated controls.

04 · Components

Semantic components, still unmistakably TURN.

Colour tells the component’s job. Shape tells its interaction type. Border and shadow tell its level. Labels and icons remain the primary meaning, so colour never carries the whole message.

06 · Adoption

Move toward the system without redesigning TURN.

The page proposes a vocabulary, not a big-bang rewrite. Adoption should happen component by component, with visual regression checks and real-device review at every step.

  1. Introduce one shared token file. Add primitives, semantic colour roles, geometry, spacing and elevation without changing existing selectors.
  2. Alias existing variables. Map --ink, --paper, --pink, --m8-pink and related variables to the new primitives so current screens remain visually stable.
  3. Normalize one component family at a time. Start with icon buttons and dialogs, then standard buttons, cards, HUD chips and The Lot rail.
  4. Replace raw semantic colours. Invalid, danger, warning, information, exit and success states should use semantic variables. Scene art and track accents may keep local raw colours.
  5. Remove orphan values only after parity review. A one-off value may encode a genuine layout constraint. Consolidate after screenshot and physical-device comparison, not through blind search-and-replace.
  6. Make this specimen executable documentation. Add component examples and state rules here whenever a new visual pattern enters TURN.

Normative proposal: preserve TURN’s black-ink construction, warm paper, saturated colour fields and tactile shadows. Standardize the hidden grammar underneath, not the personality players already recognize.
