TURN DESIGN SYSTEM

A living reference built from TURN’s production interface. The system keeps the black-ink construction, warm paper, tactile shadows and saturated colour fields while assigning a stable meaning to every reusable colour and shape.

01 · Current state

Standardize the grammar, not the personality.

TURN’s identity is already coherent. The design system consolidates hidden implementation variation while protecting expressive track art, scene colour and deliberate asymmetry.

Keep

Chunky ink construction

Near-black outlines, cream surfaces, hard offset shadows, heavy type and saturated fields remain TURN’s defining visual language.

Consolidate

Semantic colour roles

Forward action, quiet utility, navigation, difficulty and driving controls now have named roles instead of unrelated raw values.

Retire

Unexplained variation

One-off radii, nearly identical shades and generic button defaults should not change the meaning of a component by accident.

02 · Colour semantics

Keep the candy shop. Label every jar.

05 · Adoption

The first two migration steps are live.

Production now has shared primitives, semantic roles and compatibility aliases. Further normalization should remain incremental and regression-tested.

  1. Shared token file: complete. Primitive colours, semantic actions, difficulty, driving controls, geometry, spacing and elevation live in design-tokens.css.
  2. Compatibility aliases: complete. Existing variables such as --ink, --paper, --pink and --m8-pink resolve to the normative primitives.
  3. Normalize component geometry incrementally. Move one component family at a time to the radius, border and shadow scales after visual parity review.
  4. Keep content expressive. Track accents, scene art, 3D worlds and car paint are not global UI semantics and may retain local colour values.
