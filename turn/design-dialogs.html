TURN dialogs

Standardize the shell, not the content.

TURN has many kinds of dialog content, but they share one production structure: a strong Paper surface, a compact heading region, one scrolling body when needed, optional actions, and an orange close control. Size is chosen from the system scale rather than invented per feature.

Dialog contract One modal at a time.
Heading receives initial focus where appropriate.
Body owns scrolling, not the whole viewport.
Close returns focus to the trigger.

Size scale

Compact. Standard. Wide. Reader.

Size describes content complexity. It should not be used to make a dialog feel important.

Compact

≤ 660px

Short decisions, simple notices and small About-style content.

Standard

≤ 760px

Feedback forms, audio settings and medium-complexity tasks.

Wide

≤ 1040px

Settings, How to Play, Achievements and multi-column configuration.

Reader

Near full screen

History and changelog. The shell is fixed; the reading pane scrolls.

Behavior

The interaction model is as normative as the border.

Modal consistency depends on focus, scrolling and dismissal behavior as much as visual styling.

1

Do not stack modal dialogs

Close the source dialog before opening another modal. Restore the source when the reader or subtask closes if that is the user’s expected return point.

2

Focus the heading first

For information-heavy dialogs, focus the labelled heading programmatically with tabindex="-1". Do not force initial focus to Close.

3

Return focus

Closing a dialog returns focus to the control that opened it. This applies to website About as well as in-game dialogs.

4

Contain scrolling

Use overscroll-behavior, stable scrollbars and an internal body so the modal shell does not slide around in short landscape viewports.

5

Dismiss outside where appropriate

Contextual reward detail can close on outside click. Task dialogs should not accidentally discard user input unless that behavior is explicitly safe.

6

Respect reduced motion

Dialog navigation should not depend on decorative animation. Scrolling and transition behavior simplify under reduced-motion preferences.
