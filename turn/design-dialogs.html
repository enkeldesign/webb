01 / TURN dialogs

A consistent frame.
A clear way back.

Shipped anatomy

Use a Paper surface, a readable heading, one scrolling body and an orange close control. Size follows the task. Focus and dismissal are part of the component contract.

02 / Sizes & reflow

Fit the task to the space.

Compact, standard, wide and reader describe content needs. Available viewport space always takes precedence over the nominal size.

Compact

660px

About and short notices.

Standard

760px

Feedback and audio settings.

Wide

1040px

Settings, guides and Achievements.

Reader

Viewport

History and changelog.

These pixel widths are authored maxima.

TURN’s historical 0.75 normalizer affects older stylesheet dimensions. Responsive rules use actual CSS pixels. Use var(--turn-target-min) from the unscaled design-scale.css for a 44px touch target, and inspect computed geometry before copying other dimensions.

Narrow or enlarged text

Wrap the title, preserve the close target and stack content columns. Use the available width without forcing horizontal scrolling through a form. Check at 200% text.

Short landscape

Reduce padding and decorative space. Keep the header and actions outside the body’s scrolling region. Respect safe areas and the usable viewport height.

04 / Focus & dismissal

Make the return journey explicit.

01 / Open

Choose initial focus deliberately

For information-heavy content, focus the labelled heading with tabindex="-1". A short input task may start at its first field. Do not automatically focus Close for every dialog.

02 / Interact

One active focus context

Keep modal background content out of keyboard interaction. Forms own their keys, and opening a dialog releases held driving actions.

03 / Read

Contain scrolling

The body owns overflow and overscroll containment. Keep focus visible and allow the final item to scroll fully into view.

04 / Close

Return focus

Return to the trigger when it still exists. If the source surface was replaced, choose a logical point in that surface rather than dropping focus onto the document body.

05 / Dismiss

Specify Escape and outside click

Use the existing modal close path for Escape. Outside-click dismissal is appropriate for reward detail; task dialogs must protect input that would otherwise be lost.

06 / Motion

Respect reduced motion

Keep navigation and state understandable with simplified transitions. Do not animate focus or rely on a wiggle to explain a task.

Contextual reward detail needs an explicit relationship.

Achievements can present a reward detail layer within its flow. Keep a single active focus context and restore the selected reward when details close. For separate tasks such as the history reader, follow the existing close-and-return orchestration. Avoid adding independent modal stacks.

05 / Implementation

Reuse the contract.

The shell below shows the class anatomy. Focus restoration, input release and dismissal belong to the existing dialog controller; markup alone does not implement them.

<dialog class="m8-dialog turn-dialog turn-dialog--standard"
        aria-labelledby="example-title">
  <article class="m8-dialog-card turn-dialog__surface">
    <header class="turn-dialog__header">
      <h2 id="example-title" tabindex="-1">Title</h2>
      <button type="button" data-turn-navigation-action
              aria-label="Close title">×</button>
    </header>
    <div class="turn-dialog__body">…</div>
    <div class="turn-dialog__actions">…</div>
  </article>
</dialog>
